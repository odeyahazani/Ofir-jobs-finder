# התאמה לפי הפרופיל המפורט של אופיר

המודל `ofir-profile-v1` משתמש בפרופיל מקצועי מצומצם ב־`data/candidate-profile.json`. המסמך המקורי, פרטי קשר וציונים אישיים אינם חלק מהקוד. העדויות מפרידות בין פרויקטי SFDI, מחקר הפלואורסצנציה, שחזור CT, מעבדות RF והיכרות אקדמית עם כלים. שני פרויקטים אינם נחשבים לשתי שנות ניסיון תעשייתי.

הציון הוא כלל לתעדוף: משימות התפקיד עד 45, חיבור לכישורים עם ראיות עד 35 ותחום מקצועי עד 20. הוא אינו הסתברות קבלה. ציון מקצועי גבוה אינו מבטל פער בדרישות. פרסום בחברה מתאימה אינו מוכיח שהתפקיד עצמו מתאים; כתובת החברה אינה מוכיחה היכן המשרה.

- **בעדיפות גבוהה**: לפחות 70, ללא פער או שאלה מרכזית שזוהו. להצגה במומלצות נדרש גם מקור פתוח שאומת ב־30 השעות האחרונות, מיקום בישראל וטרם הוגשה מועמדות או סומנה כלא מתאימה.
- **שווה בדיקה**: חיבור מקצועי עם דרישה שצריך לברר, ניסיון של שנה–שנתיים, טקסט חסר או ציון ביניים. תג האימות במקור נשאר נפרד.
- **פער בדרישות או במיקוד**: למשל שלוש שנות ניסיון ומעלה, ניהול, תחום שאינו מתאים או כלי חובה שאינו מתועד. המשרה נשארת זמינה לעיון ולסימון אישי.

החילוץ מבוסס כללים, אינו מבין כל ניסוח אפשרי, ומציג ציטוטים כדי לאפשר בדיקה. דרישה שלא זוהתה אינה הוכחה שאינה קיימת. רענון הפרופיל אינו רענון של מקור המשרה.

## הפעלה בפרויקט קיים

1. ב־Supabase SQL Editor מריצים פעם אחת את **כל** `supabase/upgrade-matching.sql`. אין מייל או ערך להחליף. הקובץ מוסיף שלוש עמודות ומעדכן את פונקציית הסנכרון; אינו מחשב ציונים או מוחק מידע. לפני השדרוג האתר ממשיך להציג ציונים קודמים בסימון מפורש. סריקה עם המודל החדש נעצרת עם הודעה ברורה אם השדרוג חסר, כדי שלא לשמור ציון בלי הסבריו.
2. ב־GitHub → Actions → Job collector → Run workflow, ענף main, בוחרים **matching-preview**. זו השוואה בקריאה בלבד לכל המאגר: בלי בקשות למקורות, כתיבה לענן או הודעות. סיכום ב־Logs וקובץ `matching-review` באזור Artifacts בתחתית סיכום ההרצה נשמרים לשלושה ימים. בתצוגה אפשר להשוות את הציון הקודם והחדש, הקטגוריה, הראיות והפערים. אפשר להריץ תצוגה מקדימה גם לפני שדרוג SQL.
3. לאחר בדיקת הדוגמאות מפעילים באותו מקום **rescore**. זה מחשב מחדש את התאמת כל הרשומות, כולל רשומות סגורות ולא מאומתות, בלי לשנות את מצב המקור, תאריכי הגילוי והאימות, ההערות, הסימונים או אירועי ההתראה. הפעולה אינה שולחת הודעות. לאחר רענון האתר מופיעות הקטגוריות החדשות.
4. סריקות חדשות משתמשות באותו מודל. משרות שאימותן התיישן עדיין צריכות סריקת מקור רגילה; חישוב התאמה אינו מחדש את האימות.

להרצה מקומית עם משתני האיסוף הסודיים שכבר הוגדרו: `python -m collector.cloud matching-preview` ולאחר בדיקה `python -m collector.cloud rescore`. מפתח מנהל נשאר בסביבת האיסוף, ואינו נדרש באתר או בקובץ ה־SQL.
